# 演示脚本（约 8 分钟）

> 目标：在无硬件条件下展示「看清楚 / 规划好 / 管得住」三条主线，以及故障、急停、复盘与审计。
> 建议 1600×1000 以上窗口；两个浏览器窗口可并排。

---

## 0. 启动

```bash
npm install
npm run build
npm start
```

打开 <http://127.0.0.1:8810>。

演示账号：

| 角色 | 工牌 | 口令 |
|---|---|---|
| 术者 赵\*峰 | `M-1042` | `2468` |
| 助手 李\*婷 | `M-1087` | `1357` |
| 临床工程师 陈\*涛 | `E-3007` | `1122` |

> 登录页点击「术者」卡片会自动填入，再点「进入控制台」。

---

## 1. 登录与病例工作台（30 s）

1. 以**术者**登录。
2. 病例列表显示 3 个脱敏病例：
   - `C-2026-1031` 张\*明 · LAD 中段重度狭窄 · 计划就绪；
   - `C-2026-1032` 李\*华 · LCX 分支 · 规划中（计划尚未签字）；
   - `C-2026-1033` 王\*国 · RCA CTO · 已完成（含完整复盘）。
3. 指出顶部：实时链路、数据年龄、告警铃、静音、用户菜单。

**可说**：病例、计划、配准、会话状态都由服务端提供；前端不缓存权威状态。

---

## 2. 术前规划（2 min）

打开 `C-2026-1031`。

1. 左侧显示脱敏患者、血管树（8 个分支，含 LAD 68% 狭窄、RCA 54% 狭窄）。
2. 中央 3D：血管、规划路径、目标环、12 线圈、体表壳。用顶部 C-ARM 预设切换 AP / LAO 30° / CRAN，观察 480 ms 缓动。
3. 右侧「磁导航可行性」：
   - 峰值场强 42.0 mT / 60 mT；
   - 峰值梯度约 0.2 T/m / 1.2 T/m；
   - 峰值力矩约 0.85 mN·m / 2.0 mN·m；
   - 最大曲率、最小余量、逐段计划。
4. 尝试 **3D 选点**：点击「选择目标」，在血管附近点击；出现「已选择目标 · 分支名」。
5. 点击「生成导航计划」：新计划出现在左侧，状态「待审核」，3 段，约 1 分钟。
6. 点击「审核签字」，输入术者口令 `2468`；计划变为「已审核」，「进入术中」可用。
7. 观察底部「影像配准」：TRE 0.9 mm ≤ 1.5 mm，置信度 92%，可点击「重新配准」。

**可说**：签字表示已核对目标、路径、约束余量；签字后计划不可静默修改，并写入审计。

> 若想演示门禁失败：打开 `C-2026-1032`，其计划默认「待审核」，「进入术中」被禁用；或点击「重新配准」直到 TRE 超限。

---

## 3. 进入术中：预检 + 双人武装（2 min）

点击「进入术中」。

1. 阶段 `REGISTERED`；左侧「飞行前预检」未运行。
2. 点击「运行预检」：9 项逐项变绿（影像、配准、计划、可行性、线圈、温升、急停、通信、存储）。
3. 点击「双人确认武装」：
   - 术者已登录；
   - 助手区输入工牌 `M-1087`、口令 `1357`；
   - 点击「确认武装」。
4. 阶段变为 `ARMED`，顶部与底部同时显示。
5. 点击「启动自动导航」：
   - 弹窗展示计划、路径长度、预计用时、目标分支；
   - 勾选「已确认患者、计划、配准、现场与急停」；
   - **按住 0.8 s** 启动。
6. 阶段变为 `AUTO_RUNNING`，导管开始沿路径推进。

**可说**：

- 预检、双人确认、启动二次确认 + 长按是三层次防误触；
- 所有命令带 `id`、`expectedState`，服务端拒绝不符阶段的命令；
- 2.5 s 未回 ack 会显示「未确认」，但状态仍以服务端广播为准。

---

## 4. 术中监督（1–2 min）

观察并指出：

- 顶部：分段 `1/3`、完成百分比、已运行、预计剩余、数据年龄、告警数。
- 中央：导管、目标环、线圈电流导致的光晕；2D DSA 左下角同步显示。
- 右侧「磁场」：B（mT）、梯度（T/m）、力矩（mN·m）、轴向/侧向力；B 曲线滚动。
- 右侧「线圈阵列」：12 路百分比、电流、温度；饱和/温升会变红/琥珀。
- 右侧「告警」与「事件流」：阶段、分段、告警、预检、命令拒绝。
- 底部：「暂停 / 接管 / 中止并回撤 / 确认在场」；右下角固定「急停」。

**人在环**：

- 每约 40 s 点击一次「确认在场」；倒计时在底部和左侧圆环显示。
- 若超时 10 s，自动暂停并弹出 `DEADMAN_TIMEOUT` 告警。

**暂停 / 继续**：

- 点击「暂停」→ 阶段 `AUTO_PAUSED`，顶部横幅显示原因。
- 点击「继续」→ 若存在未确认高危告警或急停锁定，会被拒绝并提示原因。
- 点击「接管」→ 阶段 `MANUAL`；重新预检 + 双人确认后才能再武装。

---

## 5. 第二客户端：故障注入（1–2 min）

在另一个浏览器窗口：

1. 以**临床工程师** `E-3007` / `1122` 登录。
2. 直接访问当前病例的术中页（或从病例列表进入）。
   - 由于会话已在进行中，工程师以**只读**身份加入；页面显示「只读观察」。
3. 点击顶部「设备」→「故障注入」。
4. 依次演示：
   - **线圈饱和**：术者屏 1 s 内出现高危告警，自动暂停，C7 线圈 100% 红色。
   - **配准残差超限**：TRE 变为 2.4 mm，告警 + 暂停。
   - **侧向力超限**：侧向力 0.62 N，告警 + 暂停。
   - **控制台链路中断**：模拟链路丢失，暂停并保持位置。
   - **清除注入**：恢复注入状态与 TRE。

**可说**：多客户端共享同一服务端会话；事件与告警通过单 WS 广播；工程师不能执行运动命令，只能注入故障与查看设备。

> 第二个窗口也可只用于展示多端同步：术者暂停时，工程师端在 1 s 内同步为 `AUTO_PAUSED`。

---

## 6. 术后：急停 / 中止 / 完成（1–2 min）

### 急停

1. 在术者屏按住右下角**急停** 0.7 s。
2. 阶段 `AUTO_PAUSED`，红色横幅「软件急停已锁定」，所有运动按钮被拒绝。
3. 点击「复位急停」→ 勾选现场安全确认 → 确认复位。
4. 阶段仍为 `AUTO_PAUSED`；必须再点「继续」。

### 中止并回撤

1. 点击「中止并回撤」。
2. 弹窗写明具体后果（立即停止推进，以 14 mm/s 回撤至入口，预计秒数）。
3. 选择原因，**按住 0.8 s** 中止。
4. 阶段 `ABORTING`（速度 −14 mm/s，进度回退）→ 完成后 `ABORTED`，弹出「器械已回撤」。
5. 点击「进入复盘」。

### 或：完整到达

- 不注入故障、按时确认在场，约 70–80 s 后到达目标，阶段 `COMPLETED`；点击「进入复盘」。

---

## 7. 复盘（1–2 min）

1. KPI：总用时、路径长度、最大梯度、最大侧向力、轨迹偏差、暂停/告警。
2. 3D：可拖动 OrbitControls 查看最终姿态；2D DSA 标记 REPLAY。
3. 播放：
   - 播放 / 暂停、0.5×/1×/2×/4×；
   - 拖动时间轴；红/紫标记对应告警/分段/阶段；
   - 点击右侧事件跳转时间。
4. 曲线：梯度、侧向力、进度，游标随播放联动。
5. 右侧「会话摘要」「事件时间轴」「审计与合规」：
   - 审计仅显示该病例相关记录；
   - 点击「校验审计链」显示有效/断点；
   - 「导出 JSON」下载完整帧、事件与审计摘要。
6. 「打印」调用浏览器打印样式（隐藏导航与控件）。

---

## 8. 设备与审计（1 min）

以工程师或质控登录 →「设备」：

- 设备：跟踪器、冷却、急停回路、链路；12 路线圈电流/负载/温度；「运行自检」。
- 审计：哈希链表格、校验、导出 NDJSON；每条含前序哈希。
- 角色：五个角色的能力矩阵与演示凭证。
- 故障注入：见第 5 节。
- 系统信息：架构、协议、安全边界。

---

## 9. 常见状态与处理

| 现象 | 原因 | 处理 |
|---|---|---|
| 「继续」不可用 | 存在未确认高危告警 / 急停锁定 | 确认告警；复位急停 |
| 自动暂停，原因「人在环确认超时」 | 超过 40 s 未确认在场 | 点击「确认在场」，确认告警，再「继续」 |
| 自动暂停，原因「控制台链路中断」 | 心跳丢失 > 5 s | 确认网络；确认告警；继续 |
| 「进入术中」不可用 | 计划未签字 / TRE 超限 | 规划页签字或重新配准 |
| 页面只剩只读 | 当前角色无运动权限 | 使用术者/助手 |
| 无法再次武装（MANUAL） | 接管后必须重新预检 | 运行预检后再双人确认 |
| 数据年龄变红、3D 冻结 | 位姿 > 200 ms | 检查链路；系统应已自动暂停 |
| 端口占用 | 另一个服务在 8810 | 停止旧进程或设置 `PORT` |

---

## 10. 重置演示

服务端为内存态；重启进程即可恢复初始病例与计划：

```bash
# Ctrl+C 停掉，再启动
npm start
```

审计 `data/audit.jsonl` 会保留；如需完全清空，删除该文件后重启。
