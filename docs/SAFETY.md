# 安全论证与危害控制

> 研究原型，非医疗器械。本文用于说明前端在系统安全论证中的**定位与边界**，不能替代 IEC 62304 / ISO 14971 / IEC 62366-1 的正式文档与验证。

---

## 1. 前端在安全论证中的定位

> 前端是「信息呈现与意图输入」通道，**不是**安全相关控制的唯一实现。所有可能导致伤害的动作，其安全性由实时层安全包络、硬件急停与看门狗保证；前端失效时系统必须进入安全状态。

由此推导出三条不可妥协的设计约束：

1. **前端不参与闭环**：不发送原始线圈电流，不做 1 kHz 伺服，不自行判定「安全」。
2. **服务端权威**：阶段、门禁、告警、命令回执均由实时服务裁决；前端本地提示与本地禁用只是「双保险」，不是替代。
3. **失效即安全**：断连、卡死、过期数据、3D 崩溃都必须导致「停止/冻结/禁止运动」，而不是「继续/外推/猜测」。

本实现中，所有运动命令都是高层意图：

```
START_PRECHECK / ARM / START_AUTO / PAUSE / RESUME / TAKEOVER / ABORT / ESTOP / PRESENCE
```

前端没有 `SET_COIL_CURRENT` 或任何直接执行器接口。

## 2. 失效模式与危害控制

| # | 危害 / 失效模式 | 可能后果 | 本原型的控制 | 残余风险 |
|---|---|---|---|---|
| H1 | 位姿数据过期仍显示为「实时」 | 术者基于错误位置决策 | 数据年龄显示；> 200 ms 冻结 3D；自动导航暂停；不进行外推 | 200 ms 内的显示误差；需实时层包络 |
| H2 | WebSocket 断连，术者不知情 | 继续操作但无响应 | 全屏链路遮罩；3D 冻结；服务端心跳丢失 5 s 自动暂停 | 重连前无法操作（符合安全默认） |
| H3 | 前端崩溃 / 浏览器被杀 | 自动导航失去监督 | 服务端看门狗在 5 s 内暂停并保持位置 | 取决于实时层实现；本原型为模拟 |
| H4 | 显示状态与服务端不一致 | 误以为已暂停/已启动 | 服务端广播阶段事件 + 快照；命令 ack 前禁用重复提交；以服务端为准 | 网络乱序；用 seq/快照恢复 |
| H5 | 误触启动自动 / 中止 | 意外运动或回撤 | 双人确认武装；启动二次确认 + 800 ms 长按；中止二次确认 + 长按；确认文案含具体后果 | 触摸硬件误触；物理急停兜底 |
| H6 | 命令重放 / 重复提交 | 重复动作 | UUID 幂等键；服务端已处理集合；UI 在 ack 前禁用 | 服务重启后幂等集合丢失（生产需持久化） |
| H7 | 越权操作 | 未授权人员启动/中止 | 服务端 RBAC + 角色矩阵；审批/故障注入二次校验 | 共享工牌；需医院身份系统 |
| H8 | 配准误差超限仍推进 | 导航偏差 | TRE 显示；> 1.5 mm 禁止武装；预检项阻断；可注入故障演示 | 真实 TRE 计算不在前端 |
| H9 | 线圈饱和 / 力超限 / 梯度超限 | 器械失控或血管损伤 | 实时告警 + 自动暂停（注入演示）；门禁阻止继续；告警需确认 | 阈值来自模拟配置，生产由实时层下发只读配置 |
| H10 | 审计被篡改 | 无法追溯 | 哈希链逐条校验；导出只读 NDJSON；UI 显示断点 | 本地文件可被删除；生产需外部锚定/WORM |
| H11 | 患者数据外泄 | 隐私合规风险 | 脱敏、无外部请求、CSP、Cookie HttpOnly、本地部署 | 终端与网络环境安全 |
| H12 | WebGL 崩溃 / 显存不足 | 3D 不可用 | 错误边界 + 上下文丢失提示；2D DSA 与数值面板仍可用 | 未实现自动切换全 2D 布局 |
| H13 | 告警淹没 | 关键告警被忽略 | 三级告警、去重、需确认、高危阻断继续、声光提示 | 未接入 IEC 60601-1-8 认证声库 |
| H14 | 人在环失效（术者离开） | 自动模式无人监督 | 40 s 在场确认 + 10 s 宽限，超时自动暂停 | 术者可在场但不专注；需培训与流程 |
| H15 | 急停无法解除 / 误复位 | 无法继续或意外恢复运动 | 急停锁定阻断所有运动；复位需术者二次确认勾选；复位后保持暂停 | 软件急停不替代硬件断使能 |

## 3. 阶段门禁与安全状态

```
REGISTERED ──(预检全绿 + 双人确认 + TRE≤1.5 + 计划已签字 + 急停未锁)──▶ ARMED
ARMED ──(二次确认 + 长按)──▶ AUTO_RUNNING
AUTO_RUNNING ──(超时/力/饱和/断连/人工)──▶ AUTO_PAUSED
AUTO_PAUSED ──(高危告警全部确认 + 急停已复位)──▶ AUTO_RUNNING
任意活动态 ──(软件急停)──▶ AUTO_PAUSED + estopLatched
任意活动态 ──(中止 + 长按)──▶ ABORTING ──(回撤完成)──▶ ABORTED
```

- **安全默认**：任何异常默认「停」，不是「继续」。
- **状态可见**：顶部固定阶段、数据年龄、告警数；底部下一步提示。
- **可解释**：拒绝原因使用稳定错误码 + 人话；命令 ack 超时明确显示「未确认」。
- **可追溯**：每个关键操作写入哈希链审计。

### 急停行为

- 软件急停：立即切断运动意图，阶段转 `AUTO_PAUSED`，`estopLatched=true`，所有运动命令被拒绝。
- 硬件急停：断使能，由硬件保证；前端只显示状态，**不依赖前端保证安全**。
- 复位：术者 + 勾选「现场安全」+ 二次确认；复位后仍保持暂停，需要单独「继续」。

### 人在环 / 看门狗

- 自动模式每 40 s 要求 `PRESENCE`；超时 10 s 自动暂停。
- 客户端每 1 s 心跳；服务端 5 s 未收到任何客户端心跳 → 自动暂停。
- 重连后先拉全量快照，再恢复增量；不假设前端状态仍正确。

## 4. 告警设计

| 等级 | 颜色/图标 | 声音 | 行为 |
|---|---|---|---|
| 高 | 红 + 图标 + 文字 | 双音重复 | 阻断「继续」直至确认 |
| 中 | 琥珀 + 图标 + 文字 | 单音 | 提示，需确认 |
| 低 | 青 + 文字 | 可选轻提示 | 仅记录 |

禁止仅用颜色区分；颜色、图标、文字至少两种编码。告警去重：同一 code 在未确认/未清除前不重复堆叠。当前告警在术中右栏展示，同时通过 toast 与声音提示。

## 5. 审计与可追溯性

- 记录：登录 / 登出、病例创建、计划生成与签字、配准复核、预检、武装、启动、暂停、继续、接管、中止、急停/复位、告警确认、故障注入、数据导出。
- 字段：`seq, ts, actorId, actorName, role, action, detail, subject, prevHash, hash`。
- 摘要：`SHA-256(seq|ts|actorId|role|action|subject|detail|prevHash)`。
- 校验：逐条重算，返回断点序号；UI 显示「链校验通过 / 断点 #N」。
- 导出：只读 NDJSON；生产环境应叠加 WORM 存储与外部时间戳。

| 标准 | 关系 |

| IEC 81001-5-1 | 网络安全；CSP、RBAC、SBOM、签名更新的设计参考 |

## 7. 明确不在范围内

- 真实 1 kHz 闭环、电流求解、安全包络、剂量计算；
- 真实 DICOM 解析、分割、配准计算；
- 导管-血管接触力学、血液流变、组织损伤模型；
- 硬件急停、脚踏、手柄、串口/相机接入；
- 临床验证、可用性总结性评估、注册申报；
- 8 h 连续运行与故障注入台架的正式验证。

## 8. 事件响应（演示用）

1. 确认现场安全，使用硬件急停（若适用）。
2. 查看顶部告警与事件流，记录时间戳。
3. 导出审计包（设备页 → 导出审计包）。
4. 复位软件急停前，必须确认原因已消除、现场无人、硬件回路正常。
5. 若发生显示/状态不一致，禁止继续，刷新页面并重新拉取服务端快照。
6. 保留浏览器控制台日志、服务端 `data/audit.jsonl` 与会话复盘 JSON。
